# 콘텐츠 자동 생성 플레이북

매월 1일 자동 생성 세션(및 수동 생성)이 이 문서를 그대로 따른다.
목표: **로아 30개 + 비올리즈 30개**를 `후보`로 만들어 노션에 올린다. (발행은 사용자가 승인해야 나감)
- 발행 주기가 2일에 1개(월 약 15개 소비)라, 매월 30개면 재고가 과하게 밀리지 않고 **매달 최신 트렌드·반응 데이터로 신선하게** 다시 뽑는 게 목적이다. 미리 몇 달치를 쌓아두면 낡은 글이 나가므로 30개를 넘기지 말 것.

---

## 0. 실행 절차 (요약)

1. 아래 "성과 참고" 대로 `automation/metrics.jsonl` · `bealiz/metrics.jsonl` 읽어 반응 좋은 주제/훅 파악.
2. 기존 `automation/candidates.yaml` · `bealiz/candidates.yaml`의 `topic`들을 읽어 **중복 주제 회피**.
3. 규칙(1~5)대로 새 후보 작성 → 각 `candidates.yaml`에 append (고유 key).
4. `git add candidates.yaml && git commit && git push` → `notion-push` 워크플로가 노션에 `후보`로 올림.
5. 사용자가 노션에서 승인/수정 → 이후 자동 동기화·발행.

---

## 1. 성과 참고 (반응 좋은 것 위주로 디벨롭)

- `metrics.jsonl` 각 줄: `{date, account, qid, title, views, likes, replies, reposts, quotes, shares}`.
- 각 글의 **최신 날짜 기록**으로 성과 평가. 핵심 지표 우선순위: **views > shares > replies > likes**.
- **잘 나간 주제 상위**는 후속편·변형(다른 각도/훅)으로 **더 판다**. 이미 있는 "100만 시리즈(후속편)" 원칙과 동일.
- **잘 나간 훅 유형**(숫자형·반전형 등)을 새 글에 더 많이 쓴다. 반응 없던 방향은 줄인다.
- ⚠️ **데이터가 적을 때(글 10개 미만 또는 조회 표본 빈약)는 성과를 과신하지 말 것.** 표본이 얇으면 우연이다. 그럴 땐 검증된 6원칙 구조 + 외부 패턴으로 폭을 넓히고, 데이터가 쌓일수록 성과 가중치를 키운다.

## 2. 외부 패턴 참고 (내 계정 밖도 봄)

- 내 글 안에서만 찾지 말 것. **터지는 스레드의 보편 패턴**을 참고해 주제·훅을 넓힌다:
  첫 줄 훅, 실패담 오프닝, 숫자·리스트, 통념 반전, "저장각" 체크리스트, 공유 유도 문장 등.
- 단, **비올리즈는 기술 팩트를 외부에서 가져오지 말 것** (아래 4번). 마케팅·마인드셋·운영 패턴만 외부 참고 허용.

## 3. 말투·형식 규칙 (양 계정 공통, 절대 지킴)

- **긴 대시(—)·짧은 대시(–) 금지.** 문장부호(마침표·쉼표·콜론)로.
- **`너 / 너는 / 너희 / 네가` 금지 → `다들`** (예: 너는→다들, 네가→다들이). `너무`·`무너지는`·`건너뛰고` 같은 정상 단어는 유지.
- **6원칙**: ① 첫 줄 훅 먼저 ② 완독 흐름(실패→반전→이유→해결→결론) ③ 저장각(체크리스트/복붙 문구/실수 포인트) ④ 공유 문장(원장/기술자 타겟, 친절히 권유) ⑤ 댓글 유도 질문(매번 다르게) ⑥ 후속편 여지.
- **제목**: `이모지 + 주제번호 + 제목`. 같은 주제 3변형은 **같은 번호·같은 이모지**로 묶는다. 카테고리/유형/마케팅 같은 단어는 제목에 넣지 않음(칸에 이미 있음).
- **유형(variant)**: 실제 훅 조합으로 표기 (예: `숫자형+반전형`). "A안/B안/스토리텔링/데이터" 같은 표기 금지.
- 한 주제당 **변형 3개 이내**, 가장 터질 것 위주.

## 4. 비올리즈 전용 가드레일 (매우 중요)

- **기술 팩트를 절대 지어내지 말 것.** 비올리즈는 속눈썹 기술을 가르치는 계정이라, 틀린 기술 정보는 신뢰를 깨뜨린다.
- 쓸 수 있는 것: **창업·상담·재연락·마케팅·가격·노쇼·마인드셋** 등 비기술 주제 + **이미 확인된 현장 팩트**(persona-notes 참고: 볼륨=자연모 1개에 여러 가닥/팬, 결 안 예뻐도 예쁘게 붙이는 게 기술, 전처리, 유지력 4체크=온습도·글루컨디션·전처리·기법, 원모·가모 밀착 후 글루 락인, 속도 vs 정확도·왕초보).
- 새 기술 주제가 필요하면 **구조만 잡고 팩트 자리는 비워 두거나 `⚠️ 팩트확인` 표시** → 사용자가 노션에서 채운다. 추측한 기술 수치·방법을 단정 서술 금지.

## 5. 출력 형식 (candidates.yaml 엔트리) — ★ 카드뉴스 구조 (신규 전부 이 형식)

각 글은 **"표지 1장 + 카드 4장 안팎(3~5장)"**의 스레드로 만든다.

- `body` = **표지(첫 글)**: 카드뉴스 첫 장/유튜브 썸네일/블로그 제목처럼 **강한 후킹**. 2~3줄, 짧게. 궁금증이나 이득을 걸고 `밑에서 ↓` 같은 유도로 다음을 열게 한다. **표지에서 내용을 다 말하지 말 것**(다 말하면 안 열어봄).
- `reply` = **카드 2·3·4·5…**: 그 줄에 하이픈 3개만 있는 `---` 로 구분해 이어붙인다. 발행 시 각 카드가 답글로 체인돼 카드뉴스처럼 넘어간다.
  - 카드는 대화하듯 **짧게(각 2~4줄), 한 카드 = 한 메시지.**
  - 완독 흐름(6원칙②)을 카드에 나눠 담는다: **카드2 = 공감/문제 → 카드3 = 진짜 이유/반전 → 카드4 = 해결책(저장각) → 마지막 카드 = 공유 문장 + 댓글 유도(매번 다르게).**
  - 카드 수는 표지 제외 **3~5장.** 내용 적으면 3장, 풍부하면 5장.

```yaml
  - key: <고유영문키>            # 기존과 안 겹치게
    title: "<이모지> <번호>. <제목>"
    category: <카테고리>
    variant: <훅 조합>           # 예: 숫자형+반전형
    recommended: true            # 3변형 중 가장 밀 것만 true
    topic: "<주제 한 줄 + 6원칙 메모 + (성과/외부 참고 근거)>"
    body: |
      <표지: 강한 후킹 2~3줄. 밑에서 이어진다는 유도>
    reply: |
      <카드2: 공감 / 문제 제기>
      ---
      <카드3: 진짜 이유 / 반전>
      ---
      <카드4: 해결책 / 저장각>
      ---
      <카드5: 공유 문장 + 댓글 유도 질문>
```

- **구분선 규칙**: 카드 사이는 반드시 그 줄에 하이픈 3개(`---`)만. 카드 본문 안에는 `---`를 쓰지 말 것.
- 표지·각 카드는 **각각 500자 이내**(스레드 1개 한도). 짧을수록 카드뉴스로 재활용하기 좋다.
- (기존 형식 = 긴 body + 댓글 1개 도 발행은 되지만, **신규는 전부 이 카드 구조로.**)
- 로아 30 + 비올리즈 30. 주제 그룹당 3변형이면 각 계정 약 10개 그룹.
- 번호는 기존 마지막 번호에서 이어서 매김.
- 이번 달 성과·트렌드가 이전과 달라졌으면 그쪽으로 주제를 새로 잡는다. 지난달 것을 관성적으로 복제하지 말 것.
